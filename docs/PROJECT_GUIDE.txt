Purpose, stack and boundaries

Parcel is an authenticated customer portal for viewing owned orders, asking order status and preparing cancellation. Only a separate explicit confirmation endpoint changes an eligible order. Cancellation affects local PostgreSQL state only: no refunds, payments, inventory or carrier integration.

Actual stack: Python 3.14 on this workstation; FastAPI, SQLAlchemy, psycopg, Alembic, Pydantic Settings, Argon2, OpenAI SDK; PostgreSQL 18 installation; Next.js 16.4.0, React 19, TypeScript, Tailwind 4; pytest, Ruff, mypy, Vitest/Testing Library, Playwright and ESLint. Exact resolved dependencies are in backend/requirements.lock and frontend/package-lock.json. No LangChain, LangGraph, vector store or MCP is used.

Architecture: browser -> same-origin Next.js /api proxy -> FastAPI routes -> business services -> query repositories/SQLAlchemy -> PostgreSQL. Agent tools invoke the same order service with a server-injected actor. Provider calls happen outside database locks. Services own transactions and also construct/write ORM records; repositories encapsulate reusable query helpers. Router and orchestration are consolidated rather than split into every file in the proposed tree.

Responsibilities

Models: base.py supplies Base/Record/UTC time; nine domain modules map users, sessions, orders, conversations, messages, pending_actions, audit_events, chat_turns and rate_buckets. Models/__init__.py registers/reexports the same classes for Alembic metadata. Schemas: StrictInput forbids extra arguments; auth/order/chat/action/error modules describe public contracts. Repositories: ownership-scoped lookups, pagination, rate upserts and health query, without independent commits.

Services: auth_service owns login/session/revocation and rate transactions; order_service owns status, action preparation, confirmation, dismissal and audits; chat_service owns conversation/turn leases, persistence and retries; query_service maps order pagination/readiness. API dependencies enforce session, Origin and CSRF; router defines endpoints. main.py supplies centralized handlers, request IDs and normalized logging. integrations/llm_client.py implements explicit mock/OpenAI modes. agents/orchestrator.py owns allowlisted strict tools, call/time/history budgets and deterministic factual output.

Frontend public layout verifies session before login rendering; authenticated layout verifies before rendering Shell. Shell owns navigation/logout/demo banner. Orders renders list/detail with pagination and refresh listeners. Chat restores conversation/history/retry identity per tab. CancellationCard confirms/dismisses/reconciles a server-issued action. api-client forwards CSRF, parses safe errors and redirects on 401; session.ts performs uncached server verification and safe diagnostics.

Customer workflows

1. Open http://localhost:3000. Anonymous protected pages redirect to /login, which displays only the sign-in panel. Sign in; the server creates opaque session and CSRF cookies. Authenticated /login redirects to /orders. Refresh verifies the same session; no refresh-token endpoint is implemented. Logout revokes the session and clears cookies/private tab storage.
2. View My orders, open an order or navigate to Support assistant. Ask Where is ORD1001?. The allowlisted status tool checks ownership and returns database status/product. Missing IDs prompt clarification; unknown/unowned IDs share unavailable responses.
3. Ask Please cancel ORD1004. PLACED/PROCESSING creates an expiring PENDING action without changing the order. Keep order dismisses it. Confirm cancellation locks the owned action then order, rechecks eligibility and atomically commits CANCELLED, saved action result and audit. Expiry requires a new request. Lost responses can use Check cancellation result; repeated confirm returns the saved outcome without provider calls.

API reference

Prefix /api/v1. Errors: { "error": { "code": "...", "message": "...", "retryable": false }, "request_id": "..." }; X-Request-ID matches. Protected mutations require Origin=http://localhost:3000 and X-CSRF-Token from csrf_token cookie. Use browser same-origin proxy; no wildcard credentialed CORS.

Method/path ; Input ; Success
POST /auth/login ; email, password ; 200 user {id,email}, provider_mode, cookies
GET /auth/me ; session cookie ; 200 identity
POST /auth/logout ; session + CSRF ; 204, revoked and cookies cleared
GET /orders ; limit 1..100 default 20; UUID cursor ; 200 items, next_cursor
GET /orders/{order_id} ; owned external ID ; 200 id, order_id, product_name, status, updated_at, version
POST /conversations ; empty JSON object ; 201 conversation_id
GET /conversations/{identity}/messages ; UUID; limit 1..100 default 50, UUID cursor ; 200 items, next_cursor; messages include action where applicable
POST /chat/messages ; conversation_id UUID, client_message_id UUID, message 1..2000 characters ; 200 message, optional action, request_id
POST /actions/{identity}/confirm ; server action UUID, empty JSON object ; 200 action_id, state, order_id, order_status, already_cancelled, request_id
POST /actions/{identity}/dismiss ; server action UUID, empty JSON object ; 200 action view; no order change
GET /health/live ; none ; 200 process alive
GET /health/ready ; none ; 200 database migration revision 0001 available, otherwise 503

422 invalid input; 401 invalid/expired session; 403 Origin/CSRF; 404 absent/unowned; 409 state/turn/content conflict; 410 expired action; 429 rate limit with Retry-After:60; 503 database/provider unavailable; 504 provider/turn deadline; 500 unexpected. Swagger at http://127.0.0.1:8001/docs, OpenAPI /openapi.json.

Only login and chat submission are rate limited: defaults 10/minute per connection-source host and authenticated UUID respectively. SHA-256 keyed counters use PostgreSQL atomic fixed-minute windows across workers. Proxy login users share one source bucket. Other endpoints have no limiter. Retrying chat consumes rate allowance but preserves the same client_message_id/content for deduplication. Confirmation idempotency uses action ID independently of rate limiting.

Database and rules

users: unique normalized email and Argon2 password hash. sessions: user FK, unique token hash, CSRF hash, expiry and revocation. orders: unique external order ID, owner FK, product, checked status, version and cancellation timestamps. conversations: owner and expiring execution lease. messages: conversation FK, checked role, text, optional action reference and unique conversation/client ID. pending_actions: owner/conversation/order, optional turn ID, cancel_order type, checked state, expiry and JSON result; unique turn/order. audit_events: actor/order/action, event type, request ID and safe metadata; unique action/event. chat_turns: unique conversation/client ID, content hash, lease, checked execution state and saved result. rate_buckets: composite key/window and atomic count. alembic_version records schema revision.

Only PLACED/PROCESSING can become CANCELLED. cancelled_at is present exactly for CANCELLED. SHIPPED/DELIVERED are ineligible. Action and order locks serialize concurrent confirms. Another action on an already cancelled order completes with already_cancelled and no second transition/audit. Provider wording cannot authorize confirmation. Chat leases serialize turns; expired leases can be reclaimed and fenced tools cannot run for an old lease. Tests use their own database schema resets; never point TEST_DATABASE_URL at valuable data.

Logging and troubleshooting

LOG_FORMAT=auto|console|json; restart after changes. Console sample: level="INFO" event="request_completed" method="POST" path="/api/v1/actions/{identity}/confirm" action="confirm" status_code=200 duration_ms=12. JSON sample: {"event":"request_completed","request_id":"example-server-uuid","method":"GET","route_template":"/api/v1/orders","action":"orders","status_code":200,"duration_ms":8}. Actual events also include UTC timestamp and safe actor/conversation/action context when available. Payloads, secrets, arbitrary URLs/parameters and exception messages are omitted. Preparation logs after commit, confirmation logs committed/replayed outcomes; transactional audit is authoritative. No durable outbox or token-cost telemetry is provided.

Database unavailable: liveness may return 200 while readiness returns 503. Check the exact configured cluster first; do not reseed/change credentials to fix a stopped DB. Occupied port: netstat -ano | findstr :8001 or :3000 identifies PID; inspect owner before reusing/stopping. Do not kill unknown processes. Proxy mismatch: set BACKEND_URL consistently, restart dev or rebuild production rewrites. Origin/session failures: use localhost rather than 127.0.0.1 in the browser; verify FRONTEND_ORIGIN and backend readiness. Only explicit 401 means signed out; other verification failures withhold private content and offer Retry.

Windows DLL policy: configure actual POSTGRES_BIN. Initialization registers DLL search directory and process PATH and defaults PSYCOPG_IMPL=python before driver import. Keep installed libpq dependencies together. No security policy changes or copied DLLs are needed. Current installed libpq loaded successfully; a future policy denial requires administrator-approved binaries. Do not repeatedly reinstall a blocked binary wheel. A mypy compiled-module denial is separate; use an approved pure-Python installation if needed. Sandbox cache-write denial can be avoided for Ruff using --no-cache; do not disable Windows security.

Known limitations

Local mock demo passed; production is not signed off. Live provider, hosted CI, backup/restore, ingress/TLS, load/security/contrast/keyboard audit and full multi-process stress remain outstanding. Login proxy source bucket is shared; most endpoints have no rate limit. UUID history pages are sorted by timestamp in the client, not chronological server cursors. Manual retry UI is not uniformly governed by the retryable flag. No customer provisioning/password recovery, automatic session refresh/rotation, conversation list, refunds, stock/carrier updates or retention policy. See the report for exact PASS/PARTIAL/BLOCKED/NOT VERIFIED distinctions.
